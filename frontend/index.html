PART-A Question-Answer

Question 1: What is the difference between SAML and OAuth?

SAML and OAuth are both used for security, but they have different purposes. SAML is mainly used for authentication. For example, in the CSC environment, I can use my CSC account to access services such as Rahti instead of having a separate login for every service. This is an example of Single Sign-On (SSO).

OAuth is mainly used for authorization. It allows one application to access some information from another service without using the user's password. For example, an application can ask permission to access certain information from a Google account.

Question 2: What is a Web Application Firewall (WAF)?

A Web Application Firewall (WAF) is a security tool that protects a web application from harmful traffic and attacks. It can help block attacks such as SQL injection and cross-site scripting (XSS).

In the three-container architecture I built in Week 4, I would place the WAF before the frontend. The traffic would be:

Route → WAF → Frontend → Backend → Database

The WAF checks incoming requests and can block suspicious requests before they reach the application.

Question 3: What is YAML and why is it used in Kubernetes/Rahti?

YAML is a simple format used for configuration files. It is commonly used in Kubernetes and Rahti to describe things such as Pods, Deployments, Services, and Routes.

For example, in my Rahti project, I use YAML files to specify which Docker image my application should use and how many replicas should run. YAML is easy to read because it uses simple indentation. JSON can also be used, but YAML is usually easier to read and write.

Question 4: What are some public APIs and how could you use one in your Week 4 application?

There are many public APIs, such as OpenWeather API, Google Maps API, and REST Countries API. An API allows one application to get data or use a service from another application.

In my Week 4 exercise, I created my own API in the backend to communicate with my database. The frontend sends a request to the backend API, and the backend gets or updates the data in the database and sends the result back to the frontend.

For example, I used an API endpoint to store and retrieve visitor information from the database. This allowed the frontend to communicate with the database through the backend instead of accessing the database directly.

This is useful because the database is kept behind the backend, which gives better control and security.

Redis Cache Service Deployment on Rahti

1. Objective

The aim of this project was to add a Redis cache service to my existing containerized application and deploy it on the CSC Rahti platform. The project already contains a frontend, backend and MySQL database. Redis was added as another service that can be used by the backend for fast temporary data storage.

2. Existing Project

My project is called lemp-containers. The GitHub repository contains the frontend, backend, database and Rahti deployment files. The Rahti folder contains Kubernetes YAML files for the different parts of the application.

The Rahti folder contains YAML files for the backend, frontend, MySQL and other Kubernetes resources. A Redis service YAML file is also present. These YAML files are used to create and manage the services in the Rahti project.
